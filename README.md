# GeoCheck AI

Локальная инженерная рабочая станция для контроля качества скважинного каротажа. Независимый студенческий прототип для хакатона 2026 года. При первом запуске сервер импортирует синтетическую GeoLab-01 и действительно выполняет анализ. Все вычисления и хранение выполняются на компьютере.

## Запуск на подготовленном компьютере

Откройте `Start-GeoCheck.cmd` и перейдите в [GeoCheck AI](http://127.0.0.1:8000). Окно сервера должно оставаться открытым. Остановка — Ctrl+C. [Swagger UI](http://127.0.0.1:8000/docs) показывает контракт API. Автономное машинное описание доступно по `/openapi.json`. Swagger UI по умолчанию загружает свои ресурсы из CDN. Основной интерфейс использует локальную сборку.

## Установка с нуля в Windows

Нужны Python 3.12 x64 с pip, Node.js 22.12+ или 24 и npm. В PowerShell из корня проекта выполните команды ниже. Для первой установки пакетов нужен интернет.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements-lock.txt
npm.cmd ci --prefix frontend
npm.cmd run build --prefix frontend
.\Start-GeoCheck.cmd
```

Если Python доступен командой `python`, используйте `python -m venv .venv` для первого шага. При переносе на другой компьютер создайте окружение заново. Файл `requirements.txt` задаёт допустимые диапазоны при обновлении зависимостей, lock-файл фиксирует проверенные версии Windows.

## Сценарий работы

1. В обзоре выберите скважину в боковой панели. Число предупреждений в верхней карточке суммирует последние проверки по всем скважинам.
2. В «Данные скважин» загрузите LAS или CSV. Откройте строки таблицы, переключите колонки, при необходимости скачайте исходник. Оригинальные байты хранятся в SQLite. Удаление скважины с её отчётами требует подтверждения.
3. В «Каротаж» включите нужные треки, задайте интервал глубин или выделите область мышью. Все треки используют общую вертикальную шкалу. Подсветка берётся из последней сохранённой проверки выбранного файла.
4. В «Контроль качества» выберите признаки, методы, порог MAD, число деревьев и долю выбросов IF. Запуск сохраняет настройки, версии, оценки и интервалы. В таблице доступны причины и максимальный score IF по интервалу.
5. В «Отчёты» откройте нужный запуск. JSON содержит весь результат, включая отсчёты графиков, единицы и построчные scores. CSV содержит таблицу интервалов. Количество предупреждений считает группы соседних строк отдельно по методу и каналу: одно измерение может попасть в несколько групп.

## Структура

```text
frontend/
  src/main.tsx            оболочка, маршруты и обзор
  src/pages/              импорт, каротаж, анализ, отчёты
  src/components/         Plotly-треки, таблицы и карточки

  app/main.py             HTTP API, транзакции и раздача сборки
  app/storage.py          модели SQLite / SQLAlchemy
  app/ingest.py           парсеры LAS и CSV
  app/ml.py               правила, предобработка и Isolation Forest
  app/modules.py          контракт и реестр вычислительных модулей
  app/schemas.py          схемы запроса и результата
  app/demo.py             генератор синтетических скважин
  evaluate.py             независимая оценка на отложенной скважине
  prepare_force.py        извлечение одной скважины из внешнего CSV
  tests/                  проверки алгоритмов, файлов и API
data/demo/                синтетическая скважина и разметка внесённых ошибок
docs/                     методика и ограничения
runtime/                  локальная БД, создаётся автоматически
```

## Разработка и тестирование

Откройте корневую папку в VS Code. Через **Python: Select Interpreter** выберите `.venv\Scripts\python.exe`. Для разработки запустите два терминала PowerShell.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --reload --host 127.0.0.1 --port 8000
```

```powershell
npm.cmd run dev --prefix frontend
```

Интерфейс разработки доступен на [порту 5173](http://127.0.0.1:5173). Vite проксирует запросы на порт 8000. После изменений для обычного запуска повторите сборку frontend. При переносе хранилища задайте переменную среды `GEOCHECK_HOME` до запуска. Для резервной копии остановите сервер и скопируйте `runtime/geocheck.sqlite`.

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
npm.cmd test --prefix frontend
npm.cmd run build --prefix frontend
.\.venv\Scripts\python.exe backend/evaluate.py
```

Чтобы подключить вычисления к другому сервису, используйте REST или импортируйте модуль `app.modules` при добавленном в путь Python каталоге `backend`. Объект модуля содержит id, название, описание, Pydantic-схемы и функцию compute. Добавьте сервис нового модуля и зарегистрируйте его в REGISTRY, затем подключите его отдельный API/экран. Текущий endpoint анализа запускает well-log-qc.

### Проверенный результат в Windows

11 тестов Pytest и 3 теста Vitest / React Testing Library прошли. Сборка TypeScript и Vite завершилась успешно. В Microsoft Edge через Playwright проверены загрузка временного CSV, появление треков Plotly, изменение интервала глубины, запуск анализа, открытие графика в отчёте, скачивание JSON и удаление тестовой скважины. На ширине 390 пикселей проверены мобильная навигация и отсутствие горизонтального переполнения страницы обзора.

В процессе тестирования Starlette предупредил о будущей смене библиотеки HTTP-клиента тестов. Vite сообщил о размере JavaScript-сборки с Plotly. Оба сообщения позволяют завершить проверки и запуск.

## Подготовка к GitHub

В корне уже есть .gitignore для рабочего окружения, локальных баз, кэшей и сборки. В репозиторий включайте исходники, оба lock-файла, документацию и разрешённые синтетические fixtures. Проверьте подготовленные изменения перед первым коммитом.

```powershell
git init
git add README.md .gitignore Start-GeoCheck.cmd backend frontend data docs
git diff --cached --stat
git commit -m "Add local GeoCheck AI workstation"
git branch -M main
```

Создайте пустой репозиторий в своём аккаунте GitHub. Замените адрес ниже на его URL и выполните команды, когда будете готовы опубликовать исходники.

```powershell
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

## Границы применения и дальнейшее развитие

Текущая версия рассчитана на локальную работу одного пользователя. Один файл представляет одну скважину. Лимит составляет 10 МиБ, 50 000 строк и 64 канала, для одного анализа выбирают до 32 каналов. Вычисления синхронные. История сохраняет версии алгоритмов, параметры и результаты, обученный Python-объект живёт в памяти во время расчёта. Параметры оформления находятся в `frontend/src/styles.css`.

Следующие направления разработки — экспертная разметка в интерфейсе, словарь кривых и преобразований единиц, проверка на реальных скважинах, очередь длительных задач, восстановление пропусков, классификация литологии и выравнивание глубины. Методика и результат проверки приведены в [описании анализа](docs/analysis.md), формат входных данных — в [памятке по данным](data/README.md).
